# Couple Ledger — PRODUCT

## 誰の・何のためのアプリか

- 利用者は「2人のペア」だけ。最初のユーザーは理央と彼女。公開SNS的な要素は一切ない。
- 目的は1つ：2人の間の「どっちが・いくら・払ったか／返すか」を、揉めずに・数秒で記録し、いま誰が誰にいくら払えば清算できるかを常に1つの数字で示すこと。
- お金の記録は信頼が本体。計算結果（純残高・割当・相殺）はサーバー側の精算エンジンが唯一の正本で、アプリはその表示と入力に徹する。アプリ側で残高を独自計算しない。

## 体験の原則

1. **記録は数秒で終わる**：支払い追加は「金額だけ」で登録できる（残りは既定値）。入力の速さが継続率を決める。
2. **残高は常に1画面1数字**：ホームを開いた瞬間に「誰が誰に・いくら」が分かる。解釈をユーザーにさせない。
3. **お金の言葉は中立に**：「借金」「返済しろ」のような圧のある表現を使わない。「○○があなたに ¥2,300」のように事実だけを書く。
4. **消えない安心**：取消・復元・変更履歴が常に見える。間違えても直せることが分かるUIにする。
5. **2人だけの静けさ**：通知バッジ合戦やSNS的な賑やかさは入れない。開いたときだけ静かに正確。

## 画面（要件定義 §4.1 の S-01〜S-13）

| コード | 画面 | 役割 |
|---|---|---|
| S-01 | 新規登録・ログイン | メール＋パスワード（Supabase Auth） |
| S-02 | 表示名設定 | ペア参加前に必須 |
| S-03 | 未連携ホーム | 招待発行・コード入力・復活申請の入口 |
| S-04 | 招待確認 | 招待者の表示名を見て「参加する」で確定 |
| S-05 | ペアホーム（主画面） | 純残高・方向・最近の支払い・追加ボタン |
| S-06 | 支払い入力／編集 | 金額先行。負担・支払者・種類・日付・約束は展開式 |
| S-07 | 精算入力／編集 | 方向確認→金額→対象の割当調整 |
| S-08 | 履歴 | 支払い／精算／約束を1本の時系列で切替・検索 |
| S-09 | 詳細・変更履歴 | 割当内訳・残額・差分・取消/復元 |
| S-13 | 変更影響プレビュー | 変更前後の残高と割当を見てから確定 |
| S-11 | 過去のペア | アーカイブ閲覧・復活申請 |
| S-12 | 復活申請確認 | 承認・拒否・取消 |
| S-10 | 設定 | 表示名・メール・パスワード・ログアウト（退会はスキーマv0.2後） |

ナビゲーション：連携中は下部タブ「ホーム／履歴／設定」。追加・編集・詳細は子画面（シート）。未連携時はタブを出さず招待・参加を中心にする。

## 実装の段階

- 第1段（今回）：S-05 ホームだけを実データ表示で作り、見た目と構造を確定する（ヒーロー先行）。
- 第2段：S-06 支払い入力と S-08 履歴（記録と閲覧の主線）。
- 第3段：S-01〜S-04 の認証・招待、S-07 精算、S-09/S-13 の詳細・プレビュー。
- 第4段：S-10〜S-12 と Realtime 同期、実機検証（AT-032）。
