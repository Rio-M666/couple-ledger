# Couple Ledger — 追加設計判断 v1.0

既決のFR-001〜FR-095を変更せずに要件定義を完了するための補助細則。

| ID | 対象 | 仕様 |
| --- | --- | --- |
| AD-001 | 通貨と金額 | JPYのみ、すべて整数円。小数・負の入力不可。支払いと実送金は1円以上。相手負担額は0円以上、支払い総額以下。 |
| AD-002 | 日付・タイムゾーン | ユーザーの「今日」はAsia/Tokyo基準。業務日付はDATE、監査時刻はUTCのTIMESTAMPTZ。実際の支払い・送金の未来日は入力不可。約束期限は未来日可能。 |
| AD-003 | 支払者負担と種類 | 支払いの種類は `split` / `gift` / `gift_promise`。奢り系の相手負担額は0。`gift_promise`は本文必須かつ関連約束1件。 |
| AD-004 | テキスト入力制限 | 表示名1〜40字、支払い名1〜200字、約束本文1〜4000字。前後空白を除き空文字禁止。検索や監査表示ではHTMLを実行せずエスケープ。 |
| AD-005 | 並び順の同点処理 | 業務日付が同じ場合は登録時刻、その後IDで決定的に順序付け。古い順の割当にも同一ルールを使用。 |
| AD-006 | 支払い・精算の更新競合 | 保存時の個別versionに加え、残高影響プレビュー時のpair ledger_revisionを照合。差分があれば409で再確認。 |
| AD-007 | 取消・復元の方式 | 支払い・精算・約束は原則論理取消とし、監査履歴を保存。取消状態の記録は通常残高対象外。復元時は現在の条件を再検証。 |
| AD-008 | 精算対象の選択 | 送金方向と一致する、金銭債務のある有効な割り勘支払いを候補とする。手動割当は送金額・対象負担額を超えない。 |
| AD-009 | 自動計算の順序 | 手動で指定した有効な希望割当を優先→残る双方向債務を古い順に相殺→残る送金を該当方向の債務へ古い順に充当→残余を前払いとして保持。 |
| AD-010 | 金額の表示 | 残高の符号はペア固定Aを基準とし、UIでは利用者視点の「あなたが支払う／相手が支払う／精算なし」に変換。相殺と現金送金を別表記。 |
| AD-011 | 通信切断と復帰 | 書込中は操作の多重送信を抑止。応答不明なら同じ冪等キーで再試行。画面復帰・再接続時は最新データ再取得。永続オフラインキューなし。 |
| AD-012 | ペア解除・復活 | 解除・復活・退会はペアを直列化して原子的に処理。解除で未使用招待を失効。復活後は以前の記録に再び編集権を与える。 |
| AD-013 | 招待保護 | 招待コードは暗号学的乱数から生成。リンクは十分長いランダムトークンを別途生成。サーバーはダイジェストのみ保持し、未ログインには招待者詳細を公開しない。 |
| AD-014 | IPレート制限 | 招待コード試行のアカウント側はFR-062の固定値。IP側は初期値として15分あたり30失敗を採用し、共有IP誤判定を計測して調整。ログインもアカウント・IP両方で保護。 |
| AD-015 | 認証後の招待復帰 | 認証完了後はリンクトークンの識別情報だけ引き継ぎ、参加確定の時点で再検証。トークンをURLやアプリログに不用意に保存しない。 |
| AD-016 | 退会と個人情報 | アカウント削除時は認証アカウント・プロフィール・セッションを削除し、共有行はペア内の匿名メンバーIDで存続。自由記述の匿名性は保証できないため注意喚起。 |
| AD-017 | 共有履歴の全削除 | 両者とも退会したペアは主DBから共有履歴と監査ログを削除。バックアップ・障害ログの削除期限は採用プランを確認して明文化し、運用ルールへ従う。 |
| AD-018 | 検索対象 | 支払い名は部分一致。フィルタはAND結合。アーカイブも同一検索条件。検索によって他のペアの存在を推測できないこと。 |
| AD-019 | エラーとUI | 検証エラーは入力欄に表示。権限・期限・競合・制限・接続切れは異なるメッセージ。失敗時に成功表示しない。 |
| AD-020 | 認可と機密情報 | ユーザーの共有行閲覧は所属チェック＋RLS。書込はHono APIからのみ実行。招待ダイジェスト、秘密鍵、冪等キー応答キャッシュはクライアントへ公開しない。 |
